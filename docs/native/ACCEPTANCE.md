会社VMの新規検証領域で、取得、起動、入力、業務集計、アクセス制御を順に確認します。合格した時点のGitコミット、DockerとComposeの版、入力名と実測結果を控えます。操作トークン、会社の接続先、実データは作業記録に貼り付けず、必要なら社内の許可された場所へ保管します。

## 初回の確認順

| 段階 | 操作 | 合格条件 | 失敗したときに見る場所 |
| --- | --- | --- | --- |
| Git取得 | 会社VMから公開HTTPS URLの `git ls-remote` | `refs/heads/main` とコミットIDが返る | Gitのproxy、許可リスト、OSの信頼CA |
| 配置 | DokployのDeployとDeploymentsログ、対象サービスの状態を照合 | 7サービス起動、`catalog-migrate` 終了0、Lakehouseがhealthy | Docker daemonとBuildKitの通信、Composeログ |
| 業務契約 | `python3 native/check_contracts.py`、Dokployのコンテナ端末で `verify` | 契約19ファイル一致。画像原本・型検査・集計など11項目。初回7ファイル、再実行0 | 検査名、固定の期待値、カタログとS3 |
| 業務処理 | 合成ファイルを生成し `medallion`、Gold参照 | 初回6ファイル、SQL14本。日次生産は2工場×7日。上限5で全14行中5行を返す | 完了印、ファイル名・列、Gold公開時刻 |
| 再実行 | 入力を変えずに `medallion` とGold参照 | 新規0、`unchanged: true`。前回と同じ公開世代 | 入力の変更、変換の版、稼働中のwriter |
| 画面・監視 | Grafana、任意GUIに接続 | 監視は標準7対象、GUI付き9対象。閲覧は認証が必要。公開した日次集計と公開世代を確認 | 各サービスの状態、ブラウザー接続経路、ゲートウェイ認証 |

## 自動試験で確かめる境界

| 検証 | 入力・操作 | 合格条件 |
| --- | --- | --- |
| 画像原本 | 合成PNGとSHA-256完了印を隔離namespaceで取込 | S3のバイト列と元のSHA-256が一致 |
| 受注、日次生産 | 部分・遅延出荷、複数実績と停止、遅延到着、不正値を含む固定fixture | 二重計上がなく、Goldの数量・率とQuarantineが独立期待値に一致 |
| 設備 | 完全重複1件と同一キー競合2件を含む5行 | 採用2点、GOOD 1点、GOOD平均24.5、最新値90・BAD |
| SQLバッチ | 合成6表セットを同じ観測日時で2回反映 | 初回の製品1件、再実行skip、SQL専用Goldから参照 |
| API認証 | 無認証、読取トークン、操作トークンを使い分ける | 無認証と操作トークンでGoldは401、読取トークンで書込みは401 |
| ファイル形式の誤り | 業務表に未定義のヘッダーを持つCSVに完了印を付けて取込 | ジョブはエラーになり、直前に公開したGoldの世代は変わらない |
| 設備障害と業務更新 | 設備の完了印を破損させ、正しい製品CSVを同時投入。完了印を修復して再実行 | 新しい業務世代を公開し、設備には前回のスナップショットを表示。部分成功と設備の更新保留を記録し、旧世代と復旧後を引き続き読める |
| 任意の閲覧構成 | 認証なしと認証付きで3画面に接続し、Lakekeeperへ更新要求 | 未認証は401、認証付き閲覧は200、更新要求は403。9対象の疎通値は1 |
| 外部Kafka CDC | 隔離brokerに新旧更新、遅延snapshot、DELETE、tombstoneを発行し、consumerを再起動 | Raw 9件、offset 0〜8で欠落・重複0。旧版が勝たず、削除後の古い追加は復活せず、再開後の新しい追加を公開 |

## 実データへ移る前に

会社のネットワークでGit・イメージ・Python依存の取得を確認し、Dokploy運用では実ホストのログと接続を確認します。実SQL ServerやKafkaを接続する場合は読取権限、証明書チェーン、保持期間と更新・取消の業務上の意味を担当者と照合します。バックアップは別環境に復元し、同じGold公開世代と原本hashを確認します。合成の試験結果は会社の実データ品質、バックアップ復元、長期運転・高負荷時の結果を含みません。[復元と運用](OPERATIONS.md)

## 運用ツールの追加構成を受け入れる

[追加ツールの手順](TOOLS.md) に沿って、標準構成と閲覧UIを同じプロジェクトで起動します。

| 検査 | 操作 | 合格条件 |
| --- | --- | --- |
| 認証 | ポータル、n8n、Explorerの各入口へ未認証でアクセス | 3入口ともHTTP 401。認証ありで画面を開ける |
| ポータル | 状態を更新し、作業を選択、InfluxDBを検索 | 9件が応答。監視・調査は3件、InfluxDBの検索は2件。モバイル幅390pxで横に溢れない |
| n8n | 同梱のワークフローをインポートして手動実行 | ワークフローが成功し、APIは `ready: true`、`blocked: false` を返す |
| メトリクス転送 | Prometheusの設定を検査し、OpenObserveへ転送。ダッシュボードのJSONを登録 | 受信側の `probe_success` が系列を返し、4パネルを登録できる |
| InfluxDB 3 | 合成設備の3点を書き込み、SQLで新しい順に検索 | 24.5、23.5、22.5。Explorerの入口が開く |
| 説明資料 | スライドを前後・選択で操作し、ブラウザーから印刷 | 全10枚が操作可能。PDFは10ページ、各ページが16:9 |

結果を記録するときは、接続元、検証したポート、認証方法、実行したワークフロー、確認したメトリクスを併記します。
