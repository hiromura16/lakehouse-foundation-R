この試作は、承認済みのGold成果物をローカルの送信待ち台帳へ保存し、外部での格納とローカルの完了印を分けて扱うものです。配送とCoreの取込・SQLite（CDC）の確定位置・Kafka ACKは別です。この台帳が埋まっても既存の取り込みやローカルのGold生成へ影響する設定は追加しません。

## 境界と進み方

1. 既存の [R2承認検査](../../native/edge/r2.py) を通った明示的なmanifestだけ受け付けます。承認分類、公開データセット、世代、各ファイルのサイズとSHA-256が一致する必要があります。再送時は入力ディレクトリを読み直しません。台帳の中のmanifestと全バイトを再検証します。
2. 不変の配送IDは既存の「データセット／公開世代／manifestのSHA-256」です。manifestは各ファイルのSHA-256を含むため、本文にも結び付きます。これは署名や承認ワークフローの代わりではありません。同じ配送IDの追加は重ねて登録しません。承認者や公開先を決める仕組みは今回追加しません。
3. 試行の開始を先に保存し、SQLiteの書込みtransactionを閉じてから送信します。既存の作成専用・内容照合・manifest最後の規則を利用します。ここにクライアント生成や実行入口はなく、他の実行経路には配線していません。試験では別のSQLiteファイルを合成宛先に見立て、外部通信しません。汎用クライアントを引数に渡すインターフェース自体は通信を強制的に遮断しません。実サービスへの接続設定・認可や既存R2コマンドの変更は今回行いません。
4. 書込みが成功を返しただけでは確定とみなしません。成果物をそれぞれ作成専用で格納し、直後に宛先から読み戻してバイト長とSHA-256を照合します。全成果物の一致を確認するまで、準備完了印となるmanifestの書込みは行いません。最後にmanifestを作成専用で格納・照合し、全ファイルの一致後にだけリモート確認を台帳に保存します。読取り不能・欠落は未確定のまま再試行、長さまたはハッシュの相違は隔離します。確認を保存してから、別のローカルtransactionで完了を記録し本文を論理削除します。宛先確定の直後に配送プロセスが終了すると、ローカルは「確認不明」です。再開後は元のバイトを既存オブジェクトと照合し、上書きせず、完了を記録します。異なる内容は隔離し、完了にしません。遠隔確定が既に台帳にある場合は再送せずローカルの完了だけを記録します。
5. 未ACK・隔離の件数およびバイト数と、完了メタデータを含む総件数に上限を持ちます。失敗には上限付きの待ち時間と試行数を適用します。上限・検証違反・内容不一致で隔離したものは、本文を自動削除しません。次に期限が来た配送を処理し、全世代の大域的な順序やexactly-onceは保証しません。

## 証拠と未検証

合成試験では、別SQLiteの宛先にmanifestまで確定した直後に配送子プロセスを強制終了し、双方のDBを新しく開き直します。到達済みの同一内容を読み戻して重複オブジェクトを増やさず、試行時刻、最後の遠隔確定、ローカルACKを別々に確認します。単一配送者のロック中でも別接続で登録できることも検査します。

[閉域CDCと合成宛先の受入](../../.github/workflows/cdc-edge-outbox.yml) では、既存の閉域Kafka・Raw・Silverが動いたまま、別SQLiteの合成宛先への読み書きだけを不通にします。成功済みの配信を基準とし、不通中の送信が未確定・未ACKのまま保存されること、その間に合成INSERTが進むこと、同じ宛先の復旧と再送の途中に合成UPDATEが進むことを照合します。最後にDELETEと読取り専用の再照合を行います。復旧時は宛先の実バイト、manifestの書込み順、配送ID別の確定とACK、再登録時にオブジェクト・試行が増えないことを検査します。対象は合成成果物だけであり、CoreからGold成果物を生成して外部に渡す実経路は検証しません。

運用上はLinuxの所有者専用ディレクトリと非共有のローカルディスクに限ります。台帳を開くたびに親ディレクトリとDBの所有者・権限を確認します。配送者用のロックは別inodeの専用ファイルを使い、既存のDB本体を生のファイル記述子で開閉しません。稼働中のロックファイルの削除・置換は行わないでください。親の経路を同じUIDの他処理が置換する競合やNFSなどの共有ストレージは想定せず、信頼できる固定パスを前提にします。DB全体の暗号化、物理消去、ディスクの予約や上限、複数ホストの配送、アクセス制御とローテーション、保管／バックアップ／復元、時刻同期、リアルタイム監視・通知はありません。未ACKの合計バイトは論理容量であり、SQLite本体とjournalの使用量を示すものではありません。試行の古さは集計のタイムスタンプから判断し、停止判断・人手での再送や隔離解消の手順は別途設計します。実際のWAN断における並行するローカル取込、外部への到達、承認済み宛先での確定、回線復旧後のデータ照合は未検証です。
